    СТОИМОСТЬ И НАБЛЮДАЕМОСТЬ

    Ресурсы без иллюзий

    Нет измерения — нет числа. Исторический результат не является текущим SLA.

    01 / ВРЕМЯ

    Wall ≠ CPU

    Wall time — время по часам, включая ожидание I/O и очередей. User + system CPU — процессорное время. В многопоточной работе сумма CPU может быть больше wall.

    02 / ПАМЯТЬ

    RSS ≠ размер кэша

    Пиковый RSS отражает резидентную память процесса в конкретном запуске. Это не объём логического кэша, не весь page cache ОС и не доказательство границ памяти всех процессов.

    03 / КОНТЕКСТ

    Результат имеет границы

    Ревизия, workload, состояние кэшей, окружение и ограничения определяют применимость результата. Пропущенное значение означает «нет измерения», а не ноль.

    ТОЛЬКО В ЭТОЙ ВКЛАДКЕ

    Приватные локальные evidence

    Файл читается локально через выбор файла. Нет отправки, сетевых запросов или сохранения в браузерное хранилище. Поле source отображается как текст, без перехода по ссылке.

    Формат git-rs-architecture-evidence/v1 · до 2 МиБ · до 500 записей

    Схема локального JSON и привязка к шагам

    Формат v1 сохранён: старые файлы поддерживаются. Необязательные flow_id и step_id — точные ID запроса и шага архитектурной карты; только совпадение обоих полей показывает evidence в карточке шага, независимо от ревизии. Без привязки запись остаётся в разделе ресурсов.

    Необязательный hotspots — массив до 50 объектов на запись: name и detail — строки до 16000 символов, self_percent — конечное число 0..100. Сумма долей не проверяется: вложенные категории не складывать.

    {
  "format": "git-rs-architecture-evidence/v1",
  "items": [{
    "id": "run-1",
    "title": "Локальный perf профиль",
    "flow_id": "точный flow.id из карты",
    "step_id": "точный step.id из карты",
    "revision": "ревизия измеренного кода",
    "scope": "mapped core",
    "workload": "описание конкретной нагрузки",
    "outcome": "результат запуска",
    "limitations": "Mapped core; служба обычно range-backed. Не production-квалификация.",
    "source": "локальный perf report",
    "hotspots": [{
      "name": "имя символа или категории",
      "self_percent": 12.5,
      "detail": "контекст self samples"
    }]
  }]
}

    Остальные поля строки (id, title, scope, revision, workload, outcome, limitations, source) и числовые wall_seconds, user_cpu_seconds, system_cpu_seconds, peak_rss_bytes остаются необязательными; пропуски, null, пустая строка и unknown означают отсутствие измерения. Числа — конечные и неотрицательные. Строки — до 16000 символов; flow_id и step_id следуют тем же правилам.

    Hotspots — доля CPU-clock samples в указанном запуске, не wall и не CPU процент production; вложенные категории не складывать. Измеренный профиль mapped core нельзя автоматически переносить на обычную range-backed службу: ограничения запуска показываются вместе с результатом.

    Файл не загружен. Приватные измерения отсутствуют.
